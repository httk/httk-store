Redefine the underlying database format¶

This guide shows how to store structures in a physical table layout of your own. The worked example keeps the sites of each structure in a table with one row per site and the columns x, y, z and symbol. Each step includes the code from two runnable example scripts: A structures record with its own sites table declares the records, and Building and checking a store with a custom sites table builds, queries and reopens a store of them.

The approach needs no change to httk-store, httk-atomistic or httk-serve. You declare your own record class, register it as a structures entry record, and declare how it serves the OPTIMADE properties. It is possible rather than easy: you take over work that the built-in records do for you.

1. Decide whether you need this¶

The built-in structure records of httk-atomistic are the supported default. Before you write your own, check whether an existing option covers the need:

  • NumericUnitcellStructureRecord stores structures as plain floats instead of exact values.

  • --records structures=NAME on httk collect --into selects which registered record a collected store uses.

  • indexes= and skip_indexes= control which indexes a store creates (see Index policy).

  • Serving existing tables serves an existing SQL database in place, in whatever layout it already has.

Write your own record when you need a specific physical layout that none of these give you.

2. Plan the tables¶

The store derives the tables from the fields of a frozen dataclass. The rules that matter here are short:

  • A scalar field (float, int, str) becomes one column.

  • A fixed-shape float tensor, Annotated[tuple[tuple[float, ...], ...], Shape(3, 3)], becomes nine inline DOUBLE columns basis_0 to basis_8.

  • A tuple of a storable dataclass, tuple[SiteRecord, ...], becomes an element table for SiteRecord plus a link table that keeps the order.

Declaring, storing, and fetching records has the full set of rules.

The store adds its own columns to every record table. sid is the local row id. _httk_role marks main rows and dependency rows (see Permanentization). store_timestamp records when the row was stored (see Store timestamps). logical_id is the lineage of the row (see Record replacement). alt_id and alt_kind link alternative representations (see Alternatives). A content-deduplicated table also has a unique content_id column.

Deduplication decides whether rows are shared. The structure table keeps the default dedup="content_id", so saving an identical structure twice returns the existing row. The site table uses dedup="none", so every structure gets its own site rows. With the default "content_id" on the site class, identical site rows would be shared between structures instead.

On SQLite the example produces these tables (indexes and constraints left out):

CREATE TABLE example_sites_structure (
    sid INTEGER NOT NULL,
    _httk_role SMALLINT NOT NULL,
    store_timestamp BIGINT NOT NULL,
    logical_id BIGINT NOT NULL,
    alt_id BIGINT NOT NULL,
    alt_kind TEXT,
    content_id TEXT NOT NULL,
    basis_0 DOUBLE NOT NULL,
    ...
    basis_8 DOUBLE NOT NULL,
    id TEXT,
    immutable_id TEXT,
    last_modified TEXT,
    PRIMARY KEY (sid)
)
CREATE TABLE example_sites_structure_sites (
    example_sites_structure_sid INTEGER NOT NULL,
    sites_index INTEGER NOT NULL,
    sites_sid INTEGER NOT NULL
)
CREATE TABLE example_site (
    sid INTEGER NOT NULL,
    _httk_role SMALLINT NOT NULL,
    store_timestamp BIGINT NOT NULL,
    logical_id BIGINT NOT NULL,
    alt_id BIGINT NOT NULL,
    alt_kind TEXT,
    x DOUBLE NOT NULL,
    y DOUBLE NOT NULL,
    z DOUBLE NOT NULL,
    symbol TEXT NOT NULL,
    PRIMARY KEY (sid)
)

DuckDB creates the same tables with VARCHAR in place of TEXT. The site table has no content_id column because it is not deduplicated. The link table row (structure sid, sites_index, site sid) places one site at one position of one structure.

3. Declare the site record¶

The record module starts with these imports, which the snippets below rely on:

import datetime
import math
from collections import Counter
from collections.abc import Callable, Mapping, Sequence
from dataclasses import dataclass, field
from typing import Annotated, Any, ClassVar

from httk.atomistic import UnitcellStructure
from httk.core.register import register_entry_record
from httk.core.storage import (
    IdentitySkip,
    Indexed,
    QueryContext,
    QueryExpression,
    QueryLiteralError,
    QueryValue,
    Shape,
    StorageInfo,
    StoredPropertyProjection,
    Unique,
    float_matrix,
)

The site record is an ordinary frozen dataclass. storage_name sets the table name. identity_name pins its content identity, so moving the module later keeps stored content ids valid.

@dataclass(frozen=True)
class SiteRecord:
    """One site: reduced coordinates and the element symbol occupying it.

    :param x: The first reduced coordinate.
    :param y: The second reduced coordinate.
    :param z: The third reduced coordinate.
    :param symbol: The chemical symbol of the atom at the site.
    """

    # identity_name pins content identity, so moving the module keeps stored ids valid.
    # dedup="none": every saved structure gets its own site rows.
    __httk_storage__: ClassVar[StorageInfo] = StorageInfo(
        storage_name="example_site", identity_name="example_site", dedup="none"
    )

    x: float
    y: float
    z: float
    symbol: str

4. Declare the structure record and its projection¶

The structure record holds the lattice basis and the ordered sites. It also carries the two store-minted ids, id and immutable_id, and an optional last_modified. These three fields are marked IdentitySkip(), so they do not take part in content identity.

@dataclass(frozen=True)
class SitesStructureRecord:
    """A periodic structure stored as a basis plus a table of sites.

    :param basis: The three lattice vectors, one per row, in ångström.
    :param sites: The sites, in order.
    :param id: The human-readable entry id; minted by the store when None.
    :param immutable_id: The per-revision immutable id; minted by the store when None.
    :param last_modified: The source modification timestamp, if stated.
    """

    __httk_storage__: ClassVar[StorageInfo] = StorageInfo(
        storage_name="example_sites_structure", identity_name="example_sites_structure", indexes=(("last_modified",),)
    )
    # store.save(structure, as_record=SitesStructureRecord) accepts any UnitcellStructure,
    # including a UnitcellStructureView loaded from a file.
    __httk_canonical_source__: ClassVar[type] = UnitcellStructure

    basis: Annotated[tuple[tuple[float, ...], ...], Shape(3, 3)]
    sites: tuple[SiteRecord, ...]
    id: Annotated[str | None, IdentitySkip(), Indexed()] = field(default=None, compare=False)
    immutable_id: Annotated[str | None, IdentitySkip(), Unique()] = field(default=None, compare=False)
    last_modified: Annotated[datetime.datetime | None, IdentitySkip()] = field(default=None, compare=False)

    def __post_init__(self) -> None:
        object.__setattr__(self, "basis", float_matrix(self.basis, 3, rows=3))
        object.__setattr__(self, "sites", tuple(self.sites))

    @property
    def type(self) -> str:
        """Expose the OPTIMADE entry type.

        :return: ``structures``.
        """
        return "structures"

    @classmethod
    def __httk_project__(cls, structure: UnitcellStructure) -> Mapping[str, object]:
        """Build the record fields from a unit-cell structure, as plain floats.

        :param structure: The structure to store.
        :return: The record fields.
        :raises ValueError: If a site is not occupied by exactly one element.
        """
        symbol_of: dict[str, str] = {}
        for species in structure.species:
            if len(species.chemical_symbols) != 1 or tuple(species.concentration) != (1,):
                raise ValueError(f"species {species.name!r} is not a single fully occupying element")
            symbol_of[species.name] = species.chemical_symbols[0]
        positions = zip(structure.fractional_site_positions, structure.species_at_sites, strict=True)
        return {
            # No __post_init__ runs on these values: they must already have the field types.
            "basis": float_matrix(structure.lattice_vectors, 3, rows=3),
            "sites": tuple(SiteRecord(x, y, z, symbol_of[name]) for (x, y, z), name in positions),
            # A projection names every field; the store mints the two ids.
            "id": None,
            "immutable_id": None,
            "last_modified": structure.last_modified,
        }

Three class-level declarations connect the record to httk₂ structures:

  • __httk_canonical_source__ names the structure class the record is built from. UnitcellStructure is the one that works for structures read from files, because UnitcellStructureView subclasses it. A NumericUnitcellStructure is refused with a TypeError.

  • __httk_project__ builds the record fields from such a structure. It must name every field not marked Skip, including id and immutable_id, which it sets to None so the store mints them.

  • The type property returns "structures", the OPTIMADE entry type.

The store validates projected values against the field types. Saving with as_record= does not run __post_init__, so the projection must return canonical values itself. That is why it calls float_matrix on the lattice vectors.

5. Declare the served properties¶

__httk_stored_properties__ maps OPTIMADE property names to a StoredPropertyProjection. A projection has a response, which computes the served value from a fetched record. It may also have a query, which translates a filter into a database predicate, and a sort.

# Served OPTIMADE properties. Unlisted nullable properties are served as null.
__httk_stored_properties__: ClassVar[Mapping[str, StoredPropertyProjection]] = {
    "structure_features": StoredPropertyProjection(response=lambda record: []),  # the one mandatory property
    "last_modified": StoredPropertyProjection(response=_last_modified),
    "elements": StoredPropertyProjection(response=_elements, query=_elements_query),
    "nelements": StoredPropertyProjection(
        response=_nelements_value, query=_integer_filter("nelements", _nelements), sort=_nelements
    ),
    "elements_ratios": StoredPropertyProjection(response=_ratios),
    "chemical_formula_reduced": StoredPropertyProjection(response=_reduced),
    "chemical_formula_anonymous": StoredPropertyProjection(response=_anonymous),
    "dimension_types": StoredPropertyProjection(response=lambda record: [1, 1, 1]),
    "nperiodic_dimensions": StoredPropertyProjection(response=lambda record: 3),
    "lattice_vectors": StoredPropertyProjection(response=_lattice_vectors),
    "fractional_site_positions": StoredPropertyProjection(response=_fractional),
    "cartesian_site_positions": StoredPropertyProjection(response=_cartesian),
    "nsites": StoredPropertyProjection(
        response=_nsites_value, query=_integer_filter("nsites", _nsites), sort=_nsites
    ),
    "species": StoredPropertyProjection(response=_species),
    "species_at_sites": StoredPropertyProjection(response=_symbols),
}

The rules for this mapping are:

  • The only property you must project is structure_features. It is the one non-nullable structures property that the store does not supply itself.

  • Unprojected nullable properties are served as null.

  • store.stored_property_plan(StructureEntry) validates the mapping. It names any missing mandatory property and rejects names that structures does not define.

  • A property projected without query= is response-only. A filter on it answers 501 “not implemented”. /info/structures does not tell response-only and filterable properties apart.

The responses are plain functions of the fetched record. The declared callable type takes object, so the example types the argument as record: Any:

# The store calls each response with a fetched SitesStructureRecord. The declared
# callable type is Callable[[object], object], hence ``record: Any``.
def _symbols(record: Any) -> list[str]:
    return [site.symbol for site in record.sites]


def _elements(record: Any) -> list[str]:
    return sorted(set(_symbols(record)))


def _nelements_value(record: Any) -> int:
    return len(set(_symbols(record)))


def _nsites_value(record: Any) -> int:
    return len(record.sites)


def _formula(counts: Mapping[str, int], order: Sequence[str]) -> str:
    divisor = math.gcd(*counts.values())
    return "".join(f"{symbol}{n if (n := counts[symbol] // divisor) != 1 else ''}" for symbol in order)


def _reduced(record: Any) -> str:
    counts = Counter(_symbols(record))
    return _formula(counts, sorted(counts))


def _anonymous(record: Any) -> str:
    # ponytail: letters A..Z only, so at most 26 elements; OPTIMADE continues with Aa, Ba, ...
    counts = Counter(_symbols(record))
    divisor = math.gcd(*counts.values())
    amounts = sorted((n // divisor for n in counts.values()), reverse=True)
    return "".join(f"{chr(ord('A') + i)}{n if n != 1 else ''}" for i, n in enumerate(amounts))


def _ratios(record: Any) -> list[float]:
    counts = Counter(_symbols(record))
    return [counts[symbol] / len(record.sites) for symbol in sorted(counts)]


def _lattice_vectors(record: Any) -> list[list[float]]:
    return [list(row) for row in record.basis]


def _fractional(record: Any) -> list[list[float]]:
    return [[site.x, site.y, site.z] for site in record.sites]


def _cartesian(record: Any) -> list[list[float]]:
    return [
        [sum(c * record.basis[k][j] for k, c in enumerate((site.x, site.y, site.z))) for j in range(3)]
        for site in record.sites
    ]


def _species(record: Any) -> list[dict[str, object]]:
    return [{"name": symbol, "chemical_symbols": [symbol], "concentration": [1.0]} for symbol in _elements(record)]


def _last_modified(record: Any) -> str | None:
    return None if record.last_modified is None else record.last_modified.isoformat()

The queries receive a QueryContext, the filter operator and its literal. context.scope("sites") reaches the site rows through the link table. On that scope, context.count counts the sites, context.distinct_count counts distinct symbols, and context.exists and context.filtered express the HAS, HAS ALL, HAS ANY and HAS ONLY operators on elements. A query must handle or reject every operator it can receive, including IS KNOWN and IS UNKNOWN. It raises QueryLiteralError for a literal it cannot use.

def _nsites(context: QueryContext) -> QueryValue:
    """The number of site rows of the structure."""
    return context.count(context.scope("sites"))


def _nelements(context: QueryContext) -> QueryValue:
    """The number of distinct ``symbol`` values among the sites."""
    sites = context.scope("sites")
    return context.distinct_count(sites, sites.field("symbol"))


def _integer_filter(
    name: str, value: Callable[[QueryContext], QueryValue]
) -> Callable[[QueryContext, str, object], QueryExpression]:
    """Filter an always-known integer property computed by ``value(context)``."""

    def query(context: QueryContext, operator: str, literal: object) -> QueryExpression:
        if operator == "IS_KNOWN":
            return context.always_true()
        if operator == "IS_UNKNOWN":
            return context.always_false()
        if operator not in {"=", "!=", "<", "<=", ">", ">="}:
            raise QueryLiteralError(f"{name} supports comparisons and IS KNOWN/IS UNKNOWN")
        if not isinstance(literal, int) or isinstance(literal, bool):
            raise QueryLiteralError(f"{name} requires an integer literal")
        left, right = value(context), context.constant(literal)
        if operator == "=":
            return context.equal(left, right)
        if operator == "!=":
            return context.not_(context.equal(left, right))
        return context.compare(left, operator, right)

    return query


def _elements_query(context: QueryContext, operator: str, literal: object) -> QueryExpression:
    """Filter ``elements`` (the distinct site symbols) with HAS ALL/ANY/ONLY and LENGTH."""
    if operator == "IS_KNOWN":
        return context.always_true()
    if operator == "IS_UNKNOWN":
        return context.always_false()
    if operator.startswith("LENGTH "):
        return _integer_filter("elements LENGTH", _nelements)(context, operator.removeprefix("LENGTH "), literal)
    if operator not in {"HAS_ALL", "HAS_ANY", "HAS_ONLY"}:
        raise QueryLiteralError("elements supports HAS ALL/ANY/ONLY, LENGTH and IS KNOWN/IS UNKNOWN")
    values = literal if isinstance(literal, tuple) else (literal,)
    if not values or not all(isinstance(value, str) for value in values):
        raise QueryLiteralError("elements requires element-symbol string literals")
    sites = context.scope("sites")
    matches = [context.equal(sites.field("symbol"), context.constant(value)) for value in values]
    if operator == "HAS_ONLY":
        others = context.filtered(sites, context.not_(context.or_(*matches)))
        return context.equal(context.count(others), context.constant(0))
    present = [context.exists(sites, match) for match in matches]
    return context.and_(*present) if operator == "HAS_ALL" else context.or_(*present)

Serving through OPTIMADE describes how stores are served. Searching and exact values describes the query protocol the predicates run on.

6. Register it as a structures record¶

The store persists the record’s registry name in its layout. Every process that opens the store must therefore know that name. For a script, a module-level call at the end of the record module is enough:

register_entry_record(name="example-sites-structure", family="structures", record="sites_layout:SitesStructureRecord")

The record= reference is a lazy "module:Class" string. It must name the module as other processes import it, here sites_layout.

For permanent use, ship a registration package instead. It is the PEP 420 package httk/registry/entries/<name>/__init__.py, provided by an installed distribution or by a directory on PYTHONPATH. The directories httk/, httk/registry/ and httk/registry/entries/ must not contain an __init__.py:

my_records/
├── httk/
│   └── registry/
│       └── entries/
│           └── sites_layout/
│               └── __init__.py
└── sites_layout.py

"""Register the sites-table structures record."""

from httk.core.register import register_entry_record

register_entry_record(name="example-sites-structure", family="structures", record="sites_layout:SitesStructureRecord")

The package must not import the record module itself. Remove the module-level call from sites_layout.py once the package exists, since a second registration of the same name raises ValueError. Check the result with:

$ PYTHONPATH=my_records python -c "from httk.core.register import known_entry_records; print(known_entry_records('structures'))"

The module registry guide in httk-core describes discovery in full.

A store can also bind a record without the registry, through entry_families= (see Entry families and schema layout). Every reopen then has to pass the same declaration, and the command-line tools below cannot use it.

7. Create the store and save¶

Declare the record for the structures family when you create the store. Then save each structure with as_record=SitesStructureRecord:

with DuckdbStore(
    path, entry_records={StructureEntry: SitesStructureRecord}, entry_ids=EntryIdScheme("example", "1")
) as store:
    nacl_sid = store.save(NACL, as_record=SitesStructureRecord)
    store.save(CSCL, as_record=SitesStructureRecord)
    plan = store.stored_property_plan(StructureEntry)  # raises if a projection is wrong
    print(f"stored-property plan for {plan.entry_type!r} is valid")

Pass as_record=. A store that declares entry families refuses to save an entry as a record its family does not declare: store.save(structure) without it raises ValueError naming the declared record, instead of writing the default httk-atomistic tables.

The example builds its two structures exactly in code:

HALF = Fraction(1, 2)


def cubic(a: str) -> list[list[Fraction]]:
    """A cubic cell with the exact edge length ``a`` (ångström)."""
    edge = Fraction(a)
    return [[edge, Fraction(0), Fraction(0)], [Fraction(0), edge, Fraction(0)], [Fraction(0), Fraction(0), edge]]


NACL = UnitcellStructure(
    cell=cubic("5.64"),
    sites=[[0, 0, 0], [0, HALF, HALF], [HALF, 0, HALF], [HALF, HALF, 0]]
    + [[HALF, HALF, HALF], [HALF, 0, 0], [0, HALF, 0], [0, 0, HALF]],
    species_at_sites=["Na"] * 4 + ["Cl"] * 4,
)
CSCL = UnitcellStructure(cell=cubic("4.12"), sites=[[0, 0, 0], [HALF, HALF, HALF]], species_at_sites=["Cs", "Cl"])

8. Query it in Python¶

The search DSL chains from the sites field into the site table. s.sites.symbol == "Cl" finds the structures that have a chlorine site. Conditions on one s.sites object apply to the same site, so the second search finds only the structures with a chlorine site near the origin. A fresh s.sites access matches its own site instead:

search = store.searcher()
s = search.variable(SitesStructureRecord)
search.add(s.sites.symbol == "Cl")  # some site is chlorine
with_chlorine = [elements(row.structure) for row in search.results(structure=s)]
print("structures with a Cl site:", with_chlorine)

search = store.searcher()
s = search.variable(SitesStructureRecord)
site = s.sites  # one traversal: both conditions hold on the same site
search.add((site.symbol == "Cl") & (site.x < 0.1))
cl_near_origin = [elements(row.structure) for row in search.results(structure=s)]
print("structures with a Cl site at x < 0.1:", cl_near_origin)

A reopened store finds the record class through its registration:

with DuckdbStore(path) as store:  # sites_layout is imported, so the registration is known
    record = store.fetch(SitesStructureRecord, nacl_sid)
    print(f"fetched {record.id}: {[site.symbol for site in record.sites]}")

9. Serve it¶

httk-serve serves the store as an OPTIMADE API. With a registration package on the import path, no extra option is needed. For a one-off, --records imports the record module, and with it the module-level registration, from the working directory:

$ httk serve optimade check sites.duckdb --records sites_layout:SitesStructureRecord
$ httk serve optimade serve sites.duckdb --records sites_layout:SitesStructureRecord

check opens the store and tests every endpoint without serving. Filters then work on the queried properties:

/structures?filter=nsites>2
/structures?filter=elements HAS ALL "Na","Cl"
/structures?sort=nelements

The httk-serve page Deploying a store as an OPTIMADE service describes --records and the other options.

10. Collect into it from workflows¶

httk collect --into stores collected structures as your record when you select it by name:

$ httk collect --into results.sqlite --id-base mydb --records structures=example-sites-structure

The collector converts each collected UnitcellStructure through the record’s __httk_canonical_source__ and __httk_project__. Records are selected by registered name only, so the record module must be importable through a registration package. A collector may also return the record directly. The httk-workflow guide Choosing record kinds covers the selection rules.

A job whose structure came from a staged input file, such as a POSCAR staged by httk job new, is collected as two entries. The second one is a file-recording alternative that carries the staged file as source_file. To collect such jobs, add this field to the structure record and set it to None in __httk_project__:

source_file: Annotated[FileRecord | None, IdentitySkipWhenNone()] = None

FileRecord comes from httk.core.files and IdentitySkipWhenNone from httk.core.storage. The field adds a reference column to the store’s files table. Without it, such a job reports a storage_error that names the missing source_file field.

11. Limitations¶

  • A tuple of a storable dataclass always goes through a link table. Inline multi-column child rows without a link table are not supported.

  • A filter on a response-only property answers 501 “not implemented”.

  • Every reopen needs the registration, whether from the module-level call, --records or a registration package.

  • Numeric structures are refused unless your projection accepts them through its canonical source.

  • The structure row’s content identity is that of your record. The same structure stored as your record and as an httk-atomistic record gives two different entries.
